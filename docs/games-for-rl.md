# 适合强化学习的游戏（入门难度）

面向已经做过格子贪吃蛇、希望选下一题的读者。原则与 [`workflow.md`](workflow.md) 一致：能本地 `step()`、动作少、失败可数。算法族见 [`algorithms-for-games.md`](algorithms-for-games.md)。

---

## 结论

**适合当下一道题的，几乎都是单机、规则确定、动作少、能自己 `env.step()` 的。** 网游大多不适合作为「难度不要太大」的下一档：延迟、部分可观测、对手、反作弊，会把「表示 / 动作 / 奖励 / 探索 / 优化器」五层诊断全部搅浑。

判断适不适合，仍用四条：观测能否写清、动作是否少、失败能否计数、能不能本地步进。四条里有一条做不到，对入门来说就先放弃。

---

## 1. 比贪吃蛇更适合打基础

这些适合练工作流本身（闭环、曲线、死因），游戏深度不如蛇。

| 游戏 | 为什么适合 | 注意 |
|---|---|---|
| CartPole / LunarLander | Gym 现成，每步都有信号，几分钟能看到学习曲线 | 连续或近似连续，和离散网格不是同一肌肉 |
| FrozenLake / Taxi | 格子、表格 Q 就够，专门练探索和稀疏奖励 | 地图小，很快见顶 |
| Catch（接下落的方块） | 观测就是一条带，动作 2～3 个 | 比蛇短，适合验证看板闭环 |
| Flappy Bird | 动作 2 个（拍 / 不拍），死因几乎只有撞管 | 塑形别做成「越贴管子越好」 |

算法上：离散格子用表格 Q；CartPole / LunarLander 更常走 PPO 或 SAC（见算法文档）。

---

## 2. 和贪吃蛇同级（推荐下一档）

能复用现成做法：网格观测、死因统计、动作掩码、Vue 看板。

| 游戏 | 为什么适合 | 会卡在哪一层 |
|---|---|---|
| **2048** | 动作 4 个，盘面就是状态，奖励 = 并块分数 | 表示够用；后期是「别把大数堵死」，类似长蛇几何 |
| **简易俄罗斯方块**（10×10 或更小） | 动作少，消行有分 | 消一行很密；活到后期要看空洞 |
| **迷你吃豆人**（一个迷宫、没有或只有 1 个幽灵） | 寻路 + 躲避 | 无幽灵 = 寻路；加幽灵 = 部分可观测 |
| **Pong** | 动作少 | 用球和板的坐标，不要先上原始像素 |
| **Breakout**（打砖块） | 比 Pong 多一点时序 | 用坐标 + 砖块位图 |
| **Connect Four** | 双人但可自对弈，盘面小 | 从「双方同一套 Q」开始 |

**最贴「蛇的下一课」的是 2048 或小 Tetris：** 中盘会吃分，后期是结构而不是反应。

---

## 3. 稍难、但仍可控制范围

| 游戏 | 条件 | 为什么开始变难 |
|---|---|---|
| MiniGrid 小门钥匙 | 先 Empty，再 DoorKey-5×5 | 稀疏奖励、必须先拿钥匙，是魔塔的玩具版 |
| Sokoban 3～4 箱子 | 推错可能无解 | 纯规划；裸 DQN 容易死磕，适合对照搜索 |
| 赛车状态版 | 速度、转角，不是像素 | 连续动作才需要策略梯度 |

不要一上来 Super Mario 全关、Atari 原始像素、或完整魔塔。

---

## 4. 网游：原则上先别碰

常见网游（吃鸡、MOBA、MMORPG、大多数 .io）对入门不友好：

- 往往不能在进程里 `env.step()`，只能截屏或读内存，观测脏，还可能违规
- 对手非平稳，曲线抖，难判断是算法还是匹配
- 动作空间大（技能栏、背包）

若一定要「像网游」：

- **自对弈的小棋：** 五子棋、Connect Four，两套策略在同一进程里打
- **自己写的极简 .io：** 例如再加第二条蛇，仍是本地 `step()`
- **Poker 简化版**（有限注、2 人）：信息不全，但规则干净

不要用官方线上服当环境。

---

## 5. 结合当前项目怎么选

已有贪吃蛇 + 看板时，下一题优先：

1. **2048** 或 **小 Tetris** — 同一套网格 DQN，看「中盘会、后期结构」会不会再出现
2. **Pong（状态向量，非像素）** — 换到反应类，验证工作流不是只能用于蛇
3. **MiniGrid DoorKey-5×5** — 专门练稀疏奖励，比魔塔小一个数量级

实验数字与迭代过程见 [`iterative-study.md`](iterative-study.md)。
