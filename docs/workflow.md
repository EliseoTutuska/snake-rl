# 陌生游戏 / 场景的强化学习工作流

面对一个没玩过的游戏或新场景，不要先选 PPO、GAE 或更大的网络。先做成能跑的最小闭环，用失败分布判断卡在哪一层，再只改那一层。本文是 [`iterative-study.md`](iterative-study.md) 里贪吃蛇实验的一般化：同一套步骤可用于格子游戏、工具 agent、能自动打分的任务。

---

## 0. 一句话

**世界、大脑、看板分开；MVP 用最笨的算法；平台出现后看死因而不是只看均分；一次只动表示、动作、奖励、探索、优化器中的一层。**

---

## 1. 先拆三块，再写算法

| 块 | 职责 | 不要做的事 |
|---|---|---|
| 世界 | `reset` / `step`、碰撞、终局、可计数的失败原因 | 不要把学习写进画面循环 |
| 大脑 | 根据观测选动作、更新参数 | 不要逐步打 HTTP 去问环境 |
| 看板 | 人玩、曲线、回放 | 不要当训练步进器 |

训练循环必须能在进程内 `env.step()`。浏览器只收快照。若第一步就把智能体接到 DOM 或截图，后面所有诊断都会被帧率和像素噪音污染。

动作空间尽量小。贪吃蛇用相对三动作（不能倒车）比四个绝对方向更干净：非法「回头」从一开始就不存在。

---

## 2. MVP：三天内必须能过拟合「会吃 / 会赢一次」

MVP 只回答一件事：**闭环通不通**，不回答「强不强」。

1. **最小观测。** 人能用的特征即可：开关、血量、距离、一张小网格。不要一上来像素 CNN。
2. **最简大脑。** 离散、确定、奖励较密 → 表格 Q 或小 DQN。连续控制再考虑策略梯度。不要用「更先进」当第一版。
3. **失败必须可数。** 至少记录：成功、撞墙、撞自己、超时、超时未完成。只有均分的曲线无法告诉你下一步改什么。
4. **先写门槛再训练。** 例如：「后 50 局均分 > 随机基线」或「墙死开始少于自撞」。没有门槛的训练只是看动画。
5. **固定一颗种子做自检，看板另算。** 种子实验用于判断改动有没有效果；带界面的一次运行只作对照。

贪吃蛇上的 MVP 是：11 个 0/1 位 + 表格 Q。它很快把均分从 0 拉到约 12，并暴露「Q 状态数 = 256 且不再涨」——这就是该停下来诊断的信号，不是该换 PPO 的信号。

---

## 3. 何时停止猛训：平台的四条信号

同时出现下面几条，再训通常无效：

- \(\varepsilon\) 已到下限（或策略熵已经很低）
- 回放池或 Q 表容量用满
- 近 \(N\) 局均分不再单调上升
- 表示相关的计数饱和（表格状态数、覆盖的网格模式）

此时把计算预算从「更多局」转到「看数据」。贪吃蛇第 0 代：5372 局、\(\varepsilon=0.02\)、256 个状态、均分 12，四条同时满足。

---

## 4. 观察什么（按信息量排序）

均分是结果，不是病因。按下表读数。

| 看什么 | 问什么 | 贪吃蛇上的例子 |
|---|---|---|
| 均分曲线 | 还在涨还是平台 | 12 → 21 → 21 → 27 |
| 死因构成 | 搜索浪费在哪 | 墙死高 = 非法动作；自撞高 = 长程几何；超时高 = 会活不会吃 |
| 每局步数 | 是早死还是空转 | 890 步/局 + 超时 = 跟尾在绕圈 |
| \(\varepsilon\) 与长度 | 探索制度是否匹配难度 | 长蛇仍随机 → 强制 \(\varepsilon=0\) |
| 单局回放 | 死前 20 步在干什么 | 钻口袋、贴食物、沿尾巴空转 |
| 合法动作数 | 掩码是否在关键状态被关掉 | 全非法时改回全 `True` → 墙死回升 |

没有回放（观看模式、\(\varepsilon=0\)）时，不要相信训练均分。训练均分里含探索噪声；观看才是当前贪心策略。

---

## 5. 诊断：五层里只打一层

从外到内问，**先改更外层**。更外层错了，换优化器几乎无效。

```
1 表示   智能体是否把不同局面看成同一个状态？
2 动作   搜索有没有大量走进一步就失败的动作？
3 奖励   即时奖励是否在优化一个假目标？
4 探索   该利用时是否还在随机？该探索时是否已经贪心？
5 优化器  回放、目标网、学习率、PPO/GAE……
```

对照本项目：

| 层 | 信号 | 动作 | 不要做 |
|---|---|---|---|
| 表示 | 状态数饱和、短中盘同分 | 网格 / 朝向对齐 / 多通道 | 加大学习率 |
| 动作 | 墙死与自撞同量级 | 掩码；禁止「全非法则全放开」 | 先上更大 CNN |
| 奖励 | 贴食物死、或永不吃只求活 | 限制塑形生效区间；超时轻于撞死 | 把 eat 改成 +100 |
| 探索 | 长蛇被 \(\varepsilon\) 杀死 | 按长度或进度关探索 | 把 \(\varepsilon_{\min}\) 调到 0.2 |
| 优化器 | 前四层已对、仍不稳 | PER、Double DQN、n-step | 第一版就上 PPO |

长程、确定、可规划的子问题（迷宫、钥匙顺序、蛇的活路）可以在表示正确后**接入启发式或搜索**，不必等策略梯度学会几何。贪吃蛇长度 ≥ 20 的跟尾属于这一条：承认 DQN 在中盘吃豆，通关靠搜索。

---

## 6. 每一轮怎么改

1. **只改一层。** 同时换观测、奖励和网络，无法解释均分为何动。
2. **写下将要看到的死因变化。** 「墙死应下降」「超时应变主因」。若均分涨了但死因与预测相反，多半是巧合或种子噪声。
3. **能接着旧权重就不要重置。** 换卷积输入才必须重置。掩码与奖励改完可以立刻作用在旧 \(Q\) 上。
4. **CLI 门槛 + 看板对照。** 固定种子的脚本决定「这次算不算过」；看板用来看行为。
5. **探测规则策略的上限。** 若纯启发式从开局就能到 35，而学习策略卡在 21，说明学习器还没达到规则已能达到的搜索质量，优先修动作与启发式，而不是再训一万局。

---

## 7. 默认路径（可当检查清单）

面对陌生场景，按这个顺序走，直到平台出现在你真正关心的指标上。

1. 写出 `reset` / `step` / 失败原因；人能玩通一局。
2. 最小观测 + 表格 Q 或小 DQN；跑到平台。
3. 看状态是否混叠。混叠 → 换观测，换能装下该观测的函数逼近。
4. 看是否大量一步失败。是 → 动作掩码；检查「全非法」兜底有没有把掩码关掉。
5. 看是否在优化塑形而不是任务。是 → 削弱或限时段塑形。
6. 看长局是否被随机探索杀死。是 → 按进度关 \(\varepsilon\)。
7. 若任务含必须留活路、必须满足资源顺序的结构 → 启发式或搜索接管后期，学习器负责前期。
8. 前七步都对了，才动 PER、网络宽度、PPO。

停止条件：失败原因已经是任务的真实难度（例如「高占用率下安全取食」），而不是实现漏洞（掩码被放开、观测看不见身体）。那时再谈更大模型和更多算力。

## 8. 和贪吃蛇实验的对照（备忘）

| 步骤 | 本项目发生的事 |
|---|---|
| MVP | 表格 Q，均分 12，256 状态饱和 |
| 换观测 | 朝上网格 DQN，均分 16–21 |
| 掩码 | 墙死从数千降到数百 |
| 错误兜底 | 摸尾 + 全 `True` → 墙死回到 24% |
| 修边界 | 两层掩码，墙死 0 |
| 后期搜索 | BFS 吃豆 / 跟尾，均分 27+，超时成为主因 |
| 未走 | PPO / GRPO；它们不修口袋几何 |
