# 游戏中的主流强化学习算法

与 [`games-for-rl.md`](games-for-rl.md) 配套：先按游戏形态选算法族，再谈变体。贪吃蛇实验见 [`iterative-study.md`](iterative-study.md)。工作流见 [`workflow.md`](workflow.md)。

---

## 结论

游戏里真正占主流的只有几族。先问「这游戏长什么样」，再选算法。

- **小离散、网格、街机：** DQN 族（你们的蛇在这里）
- **连续控制：** PPO 或 SAC
- **棋类、可完美模拟：** AlphaZero / MCTS
- **电竞级复杂：** 先模仿，再 PPO/IMPALA + 自对弈
- **样本极贵：** Dreamer / MuZero

对「难度不要太大」的单机小游戏：离散用 **DQN**，连续用 **PPO 或 SAC**。只有要下棋或要少采样时，才上搜索或世界模型。

---

## 1. 价值学习（DQN 族）

学 \(Q(s,a)\)，贪心选动作。适合：动作少、离散、画面或网格、每步都有反馈。

| 算法 | 角色 |
|---|---|
| **DQN** | 卷积 + 回放 + 目标网，Atari 的起点 |
| **Double / Dueling DQN** | 减轻 Q 高估；把「状态好不好」和「动作差多少」拆开 |
| **Rainbow** | Double、Dueling、优先回放、多步、分布价值等的集成，Atari 上长时间的标配 |
| **C51 / QR-DQN** | 学回报分布，不只学期望 |
| **R2D2 / IMPALA** | 大规模分布式、LSTM，长时序 Atari / DMLab |

对应书上第 1 章的 \(Q\) 与贝尔曼方程。格子、三个相对动作、确定转移，没有必要第一版就离开这一族。

---

## 2. 策略梯度 / Actor-Critic（PPO 族）

直接学 \(\pi(a|s)\)，常用 Critic 估 \(V\) 或优势。适合：连续动作、动作很多、要保持随机探索。

| 算法 | 角色 |
|---|---|
| **A2C / A3C** | 同步 / 异步 Actor-Critic，早期大规模训练 |
| **PPO** | 裁剪更新、相对稳，**现在游戏工业里最常见的默认**（如 Dota 2 OpenAI Five、许多赛车） |
| **SAC** | 最大熵，连续控制（赛车、机械臂）很常用 |
| **IMPALA** | 高吞吐 off-policy Actor-Critic，DeepMind 打游戏常用基础设施 |

对应书上第 2 章：REINFORCE → 基线 → Actor-Critic → GAE，在工程上收敛成 PPO。

PPO 不是「更强的 DQN」，是另一条线。离散小动作空间上，它不自动比 DQN 更会绕路或留活路。

---

## 3. 搜索 + 学习（AlphaZero 族）

适合：规则确定、全信息、能模拟很多步的棋类，不是反应类。

| 算法 | 角色 |
|---|---|
| **MCTS** | 在规则里往前搜 |
| **AlphaGo / AlphaZero** | 策略网提议、价值网估价、自对弈 |
| **MuZero** | 连规则模型一起学，Atari 和棋都能打 |

围棋、象棋、将棋是主场。贪吃蛇的跟尾 / 哈密顿环是**手工搜索**，和 AlphaZero 同属「别只靠一步 \(Q\)」，但不必上完整 MCTS。

---

## 4. 世界模型（Model-based）

先学「环境下一步会怎样」，再在想象里规划或训策略。

| 算法 | 角色 |
|---|---|
| **World Models / DreamerV3** | 在潜空间里做梦再学习，样本效率高 |
| **MuZero / EfficientZero** | 规划和价值结合，Atari 上很强 |

适合模拟贵、真交互少的时候。`step()` 极便宜的格子环境，通常先把 DQN 做对。

---

## 5. 模仿 + 强化学习

人类或脚本先会玩，再微调。

| 做法 | 角色 |
|---|---|
| **行为克隆（BC）** | 对着录像学「这种局面这么走」 |
| **GAIL 等** | 对抗式模仿 |
| **先 BC 再 PPO/DQN** | AlphaStar、许多游戏 AI 的实际流水线 |

网游、MOBA、开放世界几乎都要这一步：纯 RL 从零摸技能栏太慢。

---

## 6. 多智能体 / 自对弈

| 做法 | 角色 |
|---|---|
| **自对弈** | 自己打自己，棋类和格斗常用 |
| **League / PFSP** | 对手池，避免循环克制（StarCraft、Dota） |
| **独立 DQN / 独立 PPO** | 每人一套脑，最简单的多蛇、多车 |

「像网游」时，非平稳对手通常比算法名词更难。

---

## 7. 按游戏形态选择

| 游戏形态 | 主流选择 | 例子 |
|---|---|---|
| 小离散、网格、街机 | DQN → Rainbow | 蛇、Pong、Breakout、2048 |
| 连续控制 | SAC 或 PPO | 赛车、飞行、关节 |
| 棋类、可完美模拟 | AlphaZero / MCTS | 围棋、象棋、四子棋 |
| 长时序、部分可观测 | PPO/IMPALA + LSTM，或先模仿 | 迷宫、第一人称 |
| 电竞级复杂 | 模仿 + PPO/IMPALA + 自对弈联赛 | Dota、StarCraft |
| 样本极贵 | Dreamer / MuZero | 想少打真环境 |

---

## 8. 和本项目的关系

8×8 贪吃蛇的迭代没有离开第 1 族。有效改动是观测、掩码和长蛇搜索，不是换成 PPO 或 GRPO。GRPO 面向「同一提示采样一组完整回答再组内比较」，不对应逐步格子 MDP。

选下一款游戏时：离散网格继续 DQN；若改做赛车状态版，再换 PPO/SAC。不要因为「更新」而在蛇上换族。
